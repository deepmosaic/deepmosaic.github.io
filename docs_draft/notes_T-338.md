### レビュー指摘の反映 (MEDIUM 1 件・2026-09-21)

> 指摘: 追加した段落は「ご契約の前でもログインして参加できる」と書いているが、**出荷版アプリ
> v2.3.7 にはログインダイアログの「組織コード」欄が無い**。見積書 (dashboard の印刷ページ) には
> 「※ 組織コードでのご参加は、対応版アプリの公開後にご利用いただけます。」の断りがあるので、
> サイトだけ先に公開すると**見積書と説明が食い違う** (見込み客がログインを試みて失敗する)。

**対応: 見積書と同じ断り書きをサイトにも置いた** (公開を待つ案は採らず、どちらの公開順でも
説明が食い違わない形にした)。`_includes/docs/07-team.html` の当該段落の直後に 1 段落を追加:

> なお、**組織コードでのご参加は、対応版アプリの公開後にご利用いただけます**（お見積書にも
> 同じご案内を記載しています）。ログインダイアログに「組織コード」欄が表示されるのは対応版からです。

- 文言の主文は dashboard `src/routes/corporate/quotes/[id]/print/+page.svelte:157` と**同一**
  (2 つの文書で表現を揃えるのが指摘の趣旨)。docs には `※` の用例が無いため頭記号は付けず
  「なお、」の地の文にした。
- 回帰テスト 1 件を追加 (計 9 件): 断り書きが**参加できる説明より後**にあること、
  対応版で増えるもの (「組織コード」欄) が書かれていること。
  → 実装前に**赤 1 件**を確認してから HTML を直した。
- 冒頭コメントの T-338 節に「**対応版を公開したら見積書側と同時にこの一文を外す**」を明記
  (片方だけ残すと再び食い違うため)。

### 文言の根拠 (実装より広い約束を書かない)

| 書いたこと | 実装の根拠 |
|---|---|
| 見積書に組織コードが載る | dashboard `src/routes/corporate/quotes/[id]/print/+page.svelte` の組織コード箱 (T-336) |
| 契約前でもログイン・参加はできる | `org_join_by_code` は `canceled` 以外に参加できる (T-334 の SQL、`get_license_v2` は所属を `status <> 'canceled'` で返す) |
| 共有枠 (込み時間) は使えない | `get_license_v2` のプラン合成は `active\|past_due` だけ。`dm_resolve_pool_sub` もプール先を `active\|past_due` に限る → **消費は個人の枠に載る** |
| アカウント数の変更はできない | `org_update_subscription` が `quoted` に対し 409 `org_not_activated` (T-334)。アプリ側も入力欄を出さない (desktop `TeamBillingTab.svelte`、T-337) |
| コードは契約後も変わらない | `org_create` の attach は `join_code` を触らない (T-334 の migration ヘッダ / desktop `docs/billing-sandbox-testing.md` S9-2) |
| 参加は対応版アプリの公開後 | desktop 出荷版 v2.3.7 のログインダイアログに「組織コード」欄が無い / 見積書側の同じ断り書き (dashboard `print/+page.svelte:157`、T-336) |
| 有効になる条件 = カードのお支払い / 請求書の発行 | S9-1 の実測 (請求書の支払リンク発行の時点で組織 `active` / `payment_method=invoice`)、カードは Checkout 完了の webhook |

## 注意点・既知の制約

- **公開順序**: このサイト変更は T-334 (SQL、適用済み) / T-335 (Worker) / T-336 (dashboard、コミット済み)
  が**本番に出てから**公開すること。先に出すと「見積書に組織コードがある」が嘘になる。
  計画の E 群の順序 (SQL → Worker → dashboard → アプリ → docs) と同じ。
- **出荷版アプリとの差**: desktop の出荷版 **v2.3.7 にはログインの「組織コード」欄が無い**
  (親 CHANGELOG の注記)。`/docs/#team` はもともと次のリリースを前提に書かれている節だが、
  **サイトだけ先に公開してもユーザーは組織コードを使えない**ため、見積書 (T-336) と同じ
  断り書きを docs にも入れた (上記「レビュー指摘の反映」)。これで**公開順序に依存せず**
  見積書とサイトの説明が一致する。
  **対応版アプリを公開したら、見積書 (dashboard) とサイトの断り書きを同時に外すこと。**
- **数値は書いていない**: 下限は `{{ ent.min_seats }}` のまま (`plans.yml` が正)。
  T-330 の「減らせる下限」の行には触れていない。
- `_data/plans.yml` の変更は**コメントのみ**。`check-plan-catalog` の対象 (金額 / 込み時間 /
  `self_serve`) は変えていない。
- **e2e は影響なし**: `e2e/*.ts` に docs の文言を見る spec は無い (grep 済み)。
