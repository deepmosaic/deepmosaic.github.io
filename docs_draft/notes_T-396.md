# T-396 メモ — 請求サイクル (暦月・JST) の公開文言

実装は desktop 側 (T-391 〜 T-395)。ここは**サイトの文言だけ**。
ユーザー確認済みの条件: 1 か月単位の自動更新・最低利用期間なし / 初月は開始日〜月末の日割り /
翌月以降は毎月 1 日に当月分 / 追加は即時日割り・削減は翌月 1 日から (返金なし) / 初期費用 ¥0。

## 判断したこと

- **`plans.yml` の行は「ラベル | 値」の 1 行**しかないので、条件の本体 (起算日・自動更新・期日) は
  `07-team.html` に置き、料金カードはその要約にとどめた (既存の「支払方法」行と同じ分担)。
- **kv 表に行を 1 つ足したので、`kv-alt` (ゼブラ) を以降 5 行ぶん入れ替えた。**
  クラスを足すだけだと同じ色が 2 行続く。
- **`company/asct.html` は「法人向け（Enterprise）の」と限定した。** このページは全プラン共通で、
  Light / Pro は Stripe の申込日起算 (1 日ではない)。限定しないと個人プランの虚偽表示になる。
- **解約条件の行 (asct) は触っていない。** 「解約手続きを行った月の末日にサービス提供が終了」は
  新しいサイクル (期末 = 翌月 1 日 0:00 JST) と同じことを言っているため。
- 「削減は次回更新から」でも **招待できる人数はすぐ削減後の数に下がる** (Worker の定員判定が
  `least(seats, pending_seats)`)。ここを「定員は当月そのまま」と書くと、実際には 409 で
  招待が弾かれて問い合わせになるので、**プール (当月そのまま) と招待枠 (すぐ下がる) を書き分けた。**

## 注意点・既知の制約

1. **旧文言「月末締め翌月請求」を断言しているテストは無かった** (`plans-payment.test.js` は
   「支払方法」行だけ、`docs-team-*.test.js` は下限と導入の流れだけ)。今回も**請求サイクルの
   回帰テストは足していない** — 文言が長く、実装 (Stripe の `billing_cycle_anchor`) と
   突き合わせる手段がサイト側に無いため。必要なら `07-team.html` の
   「ご請求のサイクル」行に対する断言 (`kvValues` を使う) を足すのが最小。
2. `docs_draft/notes_T-252.md` / `notes_T-298.md` に旧文言が残っているが、**過去のメモなので
   直さない** (当時の記録として正しい)。
3. サイトの公開は Actions (master への push)。**Worker / SQL より先にこの文言を出すと、
   実装が追いつくまで「毎月 1 日」が嘘になる** — T-397 の順序 (SQL → Worker → サイト) を守ること。
